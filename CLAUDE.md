# Working with this repo's owner

The owner has **zero coding experience**. This changes how every response
should be written, not just this one:

- **Never assume familiarity with git, the terminal, npm, SQL, or any
  developer tool.** Explain what a thing is before using it.
- **Every instruction must say exactly where to do it**, by name — e.g.
  "in the Neon SQL Editor (the page you already have open)", "in the
  Vercel dashboard, under Settings", "I'll run this myself, you don't
  need to do anything." Never say "run this command" without saying
  which app/window/tool it goes in.
- **Prefer doing things yourself** (via tools) over handing the user a
  command to type, whenever possible. Only ask them to do something
  manually when it truly requires their access (a dashboard only they
  can log into, a secret only they hold).
- **One step at a time.** Don't bundle multiple actions into one
  instruction — number them, and wait for confirmation before assuming
  a step worked.
- **No jargon without a plain-language explanation the first time it's
  used** (e.g. "migration" = "a file that changes the database's
  structure").
- Keep explanations short. Simple and correct beats thorough and
  technical.
